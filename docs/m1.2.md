# M1.2 — Preference-aware recommendation

M1.2 connects listening history to ranking and adds transparent recommendation explanations.

## Flow

Listening events -> decayed preference score -> CandidateSignals.preference_score -> fusion -> explanation.

Preference is currently track-local. A liked track receives positive evidence and disliked/skipped tracks receive negative evidence. Evidence decays with a 30-day half-life by default.

The preference signal is bounded to [-1, 1] so it cannot overwhelm the other retrieval channels. This is an initial engineering model, not a claim about universal user behavior.

## Explanation

Every ranked candidate exposes the six fusion contributions: metadata, DSP, learned, preference, novelty, and diversity. The explanation stores the raw signal, normalized weight, and weighted contribution.

## Deliberate limitation

M1.2 does not infer preference for an unseen track merely because it sounds like a liked track. That requires Music DNA feature-space generalization and belongs in the next preference-learning layer.
