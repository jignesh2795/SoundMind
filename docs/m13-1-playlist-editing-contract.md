# M13.1 — Deterministic Playlist Editing Primitives

## Purpose

M13.1 introduces an explicit structural-editing boundary for playlists that have already been generated by the existing M2 sequencing layer.

The editor changes playlist membership and order only. It does not re-rank candidates, recompute recommendation scores, or replace the M2 sequencing algorithm.

## Scope

M13.1 provides four deterministic edit operations:

- remove an existing track;
- move an existing track to an absolute zero-based position;
- swap two existing tracks;
- trim the playlist to a positive prefix length.

Edits are applied sequentially in the order supplied by the caller.

## Contract

apply_playlist_edits(items, edits) accepts a tuple or list of SequenceItem values and returns a new immutable tuple.

The input playlist must contain non-empty, unique track IDs.

### Remove

RemoveTrack(track_id) removes exactly one existing track.

A missing or empty track ID is rejected.

### Move

MoveTrack(track_id, position) moves an existing track to the requested zero-based playlist index.

The position must be an integer within the current playlist bounds.

### Swap

SwapTracks(first_track_id, second_track_id) exchanges the positions of two existing tracks.

Both track IDs must exist and must be distinct.

### Trim

TrimPlaylist(limit) retains the first limit items.

The limit must be a positive integer.

## Determinism and immutability

The editor has no network, model, random, or time dependency.

Edits operate on a private working copy. The caller's input tuple/list is never mutated.

Repeated application of the same edits to the same input produces the same result.

## Boundary

Playlist editing sits after generation/sequencing:

```
retrieval
    ↓
M1 ranking
    ↓
M2 sequencing
    ↓
generated playlist
    ↓
M13.1 structural editing
    ↓
edited playlist
```

The edited playlist is an output artifact. Editing does not feed changes back into M1 ranking or silently alter M2 sequencing behavior.

## Not included

M13.1 does not provide:

- natural-language edit interpretation;
- semantic filters such as genre, mood, or energy;
- automatic replacement-track discovery;
- persistent playlist storage;
- external playback-provider integration;
- LLM or cloud-service dependency.

Those capabilities can be added later behind explicit contracts.
